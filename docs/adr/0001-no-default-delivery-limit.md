# 최대 전달 횟수 기본값은 무제한이고, 메시지를 소리 없이 버리지 않는다

큐의 최대 전달 횟수는 기본값이 무제한이고, 한도를 지정하려면 dead letter 큐도 함께 지정해야 한다(아니면 선언 오류). dead letter 큐가 없는 큐에서 reject하면 오류가 나고 메시지는 리스에 남는다. RabbitMQ 4.x 쿼럼 큐는 기본 한도 20회에 dead letter 대상이 없으면 메시지를 버리지만, smq는 내구성 큐가 사용자 몰래 메시지를 잃는 쪽보다 독이 든 메시지(poison message)가 무한 재시도되는 쪽을 사용자가 설정으로 막게 하는 편을 골랐다.

## Considered Options

- 기본 20회, dead letter 큐가 없으면 버림 (RabbitMQ 4.x): 설정 없이도 무한 재시도를 막지만 소리 없는 유실이 생긴다.
- 기본 20회, dead letter 큐가 없으면 더는 꺼내지지 않는 상태로 큐에 남김: 유실은 없지만 ready, 리스 중, 지연 어디에도 속하지 않는 새 상태가 생긴다.
