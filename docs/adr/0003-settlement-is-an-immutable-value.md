# 공개 API의 정산은 불변 값이고, 청크는 정산 상태를 기억하지 않는다

컨슈머는 꺼낸 청크로 `Settlement` 값을 만들고(`chunk.settle().nack(..).reject(..).ackRest()`) `queue.settle(settlement)`로 반영한다. `Chunk`는 메시지와 리스 기한, 숨긴 리스 토큰만 가진 불변 record다. 정산 한 번이 저장소 트랜잭션 한 번이라는 사실이 API 모양에 그대로 드러나고, 효력 불명 예외 뒤에는 같은 값을 다시 반영하면 되며(이미 반영됐다면 `STALE`), 청크를 여러 스레드에 넘겨도 안전하다. 이것이 성립하려면 정산된 메시지는 그 리스에서 풀려야 한다. 같은 리스로 다시 정산하거나 연장하면, 메시지가 아직 아무도 다시 꺼내지 않은 준비 상태라도 `STALE`이다. 대가로 "나머지 전부"는 정산 값 하나 안에서만 계산된다. 여러 번 나눠 정산한 뒤 `ackRest()`를 하면 앞서 정산한 메시지가 다시 담겨 `STALE`로 돌아온다.

## Considered Options

- 정산 상태를 기억하는 `Chunk` 핸들(`chunk.ack(id)`, `chunk.ackRest()`): 나눠서 정산해도 "나머지"가 맞게 계산되지만, 메시지마다 SQLite 쓰기 트랜잭션이 하나씩 생기고, 핸들이 스레드 안전해야 하며, 효력 불명 예외 뒤에 핸들이 기억하는 상태가 저장소와 어긋난다.
