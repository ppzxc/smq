# SQLite 스키마는 열 때 자동으로 업그레이드하고, 옛 프로세스는 트랜잭션마다 버전을 확인해 멈춘다

SQLite 파일은 smq 전용이다. `PRAGMA application_id`에 smq 고유 상수를, `PRAGMA user_version`에 라이브러리 버전과 따로 두는 스키마 버전 정수를 기록한다. 열 때 버전이 낮으면 `BEGIN IMMEDIATE` 트랜잭션 하나 안에서 버전을 다시 읽고 자동으로 업그레이드한다. 버전이 높거나 smq 파일이 아니면 `IncompatibleStorageException`으로 거부한다. 같은 파일을 여러 프로세스가 공유하므로, 새 버전 프로세스 하나가 업그레이드하는 동안 옛 버전 프로세스가 아직 돌고 있을 수 있다. 그래서 모든 저장소 트랜잭션은 시작할 때 `user_version`을 다시 읽는다. 열 때의 버전과 다르면 예외를 던지고, 그 `Smq` 인스턴스는 영구히 실패한 상태가 된다. 옛 프로세스가 쥐고 있던 리스는 그대로 남았다가 만료되어 재전달되므로 at-least-once가 깨지지 않는다. 이 규칙은 스키마를 저장소 구현 내부에서 다룬다는 전제 위에 있다. SPI에는 연산을 추가하지 않는다.

## Considered Options

- 명시적 업그레이드(빌더 옵션이나 별도 진입점을 써야만 업그레이드하고, 없으면 거부): 운영자가 업그레이드 시점을 정할 수 있지만, 임베디드 라이브러리 사용자가 배포 절차를 하나 더 알아야 한다. 또 업그레이드 뒤에도 남아 있는 옛 프로세스를 감지하는 장치가 필요한 것은 똑같다.
- 열 때만 버전을 확인한다: 비용은 없지만, 실행 중에 다른 프로세스가 업그레이드하면 옛 프로세스가 새 스키마에 옛 SQL을 실행한다. 헤더 필드를 한 번 읽는 비용은 µs 수준이라 트랜잭션마다 확인하는 쪽을 골랐다.
- `smq_meta` 테이블에 버전을 기록한다: PostgreSQL과 모양이 비슷해지지만, 파일이 smq 전용이라 헤더 필드를 앱과 나눠 쓸 일이 없다. 헤더 필드는 테이블 없이 읽을 수 있고 트랜잭션과 함께 원자적으로 바뀐다.
