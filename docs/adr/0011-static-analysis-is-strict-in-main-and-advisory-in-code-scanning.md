# 정적 분석은 main에서 엄격히 강제하고 CodeQL은 비차단으로 운영한다

smq는 Error Prone, NullAway, JSpecify, Spotless, CodeQL을 함께 사용한다. main은 Error Prone 경고와 NullAway 위반을 빌드 오류로 처리하고, test와 benchmark는 NullAway의 적용 대상에서 제외한다. 공개 API는 기본 non-null 계약을 따르며 실제로 null을 허용하거나 반환하는 위치에만 `@Nullable`을 명시한다. 이 조합은 컴파일 단계에서 결함과 계약 위반을 막되, 테스트 코드의 도입 비용을 제한한다.

JSpecify는 우선 컴파일 전용 API 의존성과 정적 전이 모듈 요구로 소비자 컴파일에 노출하고, 일반 및 모듈 경로 소비자 테스트가 이를 검증한다. 이 조합이 검증에 실패할 때만 런타임 전이 의존성으로 승격한다. CodeQL은 PR, main push, 주간 일정에서 main Java 소스를 모두 분석해야 하며, 소스 분석 모드가 이를 충족하지 못하면 수동 빌드 분석으로 전환한다. CodeQL 결과는 보안 알림으로 제공하되 릴리스 게이트를 막지는 않는다.

`@Nullable`은 JSpecify가 의미를 정한 타입 사용 위치에만 붙인다. Error Prone 억제는 필요한 가장 좁은 요소에 두고, 인접한 주석으로 의도된 동작 또는 도구 한계를 설명한다. 첫 CodeQL 실행의 분석 범위는 PR 본문에 기록하지만, 외부 도구 로그에 의존하는 별도 CI 게이트는 두지 않는다.

포맷 도입은 설정과 일괄 포맷을 분리하되 각 커밋이 `check`를 통과해야 한다. nullable 공개 계약은 선언에 그치지 않고 해당 런타임 동작을 보이는 테스트로 검증한다. CodeQL의 예약 분석은 매주 월요일 03:00 UTC에 실행한다.

Spotless 설정은 첫 커밋에서 제공하되 `check` 연결은 일괄 포맷 결과와 함께 두 번째 커밋에서 활성화한다. 첫 CodeQL 실행이 main Java 전체를 분석하지 못하면 같은 변경에서 수동 빌드 분석으로 전환해 다시 검증한다. 보안 경고 자체는 비차단이지만, CodeQL 설정이나 분석 실행이 실패하면 워크플로는 실패로 표시한다.

## Considered Options

- test와 benchmark에도 NullAway를 강제한다: 널 계약의 신호 대 잡음 비가 낮아져 이 도입 범위에서는 제외한다.
- JSpecify를 처음부터 런타임 의존성으로 공개한다: 어노테이션만으로 필요한 런타임 의존성을 늘리지 않는다.
- CodeQL을 필수 릴리스 게이트로 둔다: 초기 분석 품질과 운영 경험을 축적하기 전에는 알림 전용으로 둔다.
- Error Prone 검사를 전역 또는 패키지 단위로 억제한다: 개별 예외의 근거가 사라져 이후 결함을 가릴 수 있다.
