# SQLite 스키마는 열 때 자동으로 업그레이드한다

[ADR 0004](0004-schema-auto-upgrade-with-per-transaction-version-check.md)를 대체한다.

SQLite 파일은 smq 전용이다. `PRAGMA application_id`에 smq 고유 상수를, `PRAGMA user_version`에 라이브러리 버전과 따로 두는 스키마 버전 정수를 기록한다. 열 때 버전이 낮으면 `BEGIN IMMEDIATE` 트랜잭션 하나 안에서 버전을 다시 읽고 자동으로 업그레이드한다. 버전이 더 높거나 smq 파일이 아니면 `IncompatibleStorageException`으로 거부한다. 이 규칙은 스키마를 저장소 구현 내부에서 다룬다는 전제 위에 있어서, SPI에는 연산을 추가하지 않는다.

버전은 열 때 한 번만 확인한다. 한 JVM만 파일을 열 수 있으므로(ADR-0012) 실행 중에 다른 프로세스가 스키마를 올릴 수 없고, 트랜잭션마다 다시 읽을 이유가 없다. ADR-0004는 여러 프로세스가 파일을 공유한다고 보고 트랜잭션마다 확인해 옛 프로세스를 멈추게 했으나, 그 전제는 ADR-0012로 사라졌고 확인과 영구 실패 상태는 #126에서 코드까지 걷어 냈다.

## 검토한 대안

- **명시적 업그레이드(기각)**: 빌더 옵션이나 별도 진입점을 써야만 업그레이드하고, 없으면 거부한다. 임베디드 라이브러리 사용자가 배포 절차를 하나 더 알아야 한다.
- **`smq_meta` 테이블에 버전을 기록(기각)**: PostgreSQL과 모양이 비슷해지지만, 파일이 smq 전용이라 헤더 필드를 앱과 나눠 쓸 일이 없다. 헤더 필드는 테이블 없이 읽을 수 있고 트랜잭션과 함께 원자적으로 바뀐다.
- **트랜잭션마다 확인(기각)**: 한 JVM 전용이라 필요 없다.
